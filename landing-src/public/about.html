How ShieldAI Protects Your Wallet

ShieldAI checks blockchain transactions before your wallet signs them, combining contract analysis, a buy and sell simulation and threat intelligence into one risk score. If a check cannot run, it says Unknown instead of Safe.

ShieldAI operates at the transaction layer, not the URL layer. It intercepts eth_sendTransaction in the browser's page context before your wallet ever receives the signature request.

What ShieldAI Does

ShieldAI is a Chrome browser extension that acts as a transaction firewall for Web3 wallets. Every time you initiate a transaction on a DApp — a swap, a token purchase, an NFT mint — ShieldAI intercepts it before your wallet receives the signature request.

The risk score combines four weighted checks: contract code (including bytecode patterns for unverified contracts), market and liquidity data, on-chain reputation, and a buy and sell simulation, together with scam databases such as GoPlus. The result is a risk score from 0 to 100 with a plain-English explanation of what was found. You always choose whether to cancel or sign.

How Risk Is Rated

Every transaction receives a risk score before you sign it. Higher means riskier:

Risk scoreVerdictWhat you see
0 – 30SAFEThe verdict and details; you can continue
31 – 49CAUTIONA warning; you choose to proceed or cancel
50 – 70HIGH RISKA strong warning with threat details
71 – 100BLOCK RECOMMENDEDThe highest risk verdict; blocking is strongly recommended

The extension shows this as a safety score, 100 minus the risk score, so higher is safer there. These are the default bands. A score in the SAFE band is still shown as CAUTION when the risk engine rates the token medium risk or the data is incomplete, and if a check could not run the result is shown as Unknown instead of a number.

Wallet Drainer Protection

A wallet drainer is a malicious smart contract that exploits ERC-20 approval functions or EIP-712 permit signatures to transfer all tokens from a wallet in a single transaction. Standard browser phishing warnings cannot detect these because they operate at the URL layer — the attack happens at the transaction layer.

ShieldAI helps against wallet drainers by:

  • Catching the transaction or signature request before your wallet shows it
  • Analyzing EIP-712 permit and Permit2 signature requests for approval exploits
  • Flagging contracts whose deployer has a history of risky deployments
  • Showing the exact asset change before you sign, when transaction simulation is enabled

Honeypot Detection

A honeypot token allows users to buy but contains hidden code that blocks all sell transactions. The token appears to have liquidity and price action, but holders can never exit.

ShieldAI looks for honeypots in two ways: it simulates a buy and a sell of the token, and it checks the contract's bytecode for known honeypot patterns, which works even for unverified contracts. If the sell simulation cannot run, the result is Unknown rather than Safe.

Pre-Sign Transaction Simulation

When transaction simulation is enabled, ShieldAI sends the transaction to Tenderly for simulation on a copy of the chain state. Tenderly runs it in a sandbox and returns the tokens and amounts that would leave or enter your wallet.

ShieldAI displays this asset delta before the wallet signature dialog appears. For example: "You will send 2.5 BNB and receive 10,000 TOKEN." If the simulation shows unexpected asset loss, the transaction is flagged HIGH RISK or BLOCK.

ShieldAI vs. Browser Phishing Warnings

Browser built-in warnings

  • Operate at the URL / domain layer
  • Cannot inspect transaction data
  • Do not analyze smart contract code
  • Cannot simulate asset loss before signing
  • Miss all on-chain attacks on legitimate sites

ShieldAI Transaction Firewall

  • Intercepts at eth_sendTransaction
  • Analyzes contract bytecode for honeypot/rug patterns
  • Simulates the asset change before signing, when enabled
  • Scores deployer history across past deployments
  • Flags risky Permit2 and approval signature requests

What Data ShieldAI Collects

ShieldAI collects the minimum data required to perform a security scan: the transaction's recipient address, sender address, value, calldata, chainId, and any EIP-712 typed data. This data is sent to the ShieldAI API over HTTPS for risk analysis.

  • Scan results are stored by contract address and chain, not with your IP address
  • Scan history (last 50 results) is stored locally in chrome.storage.local — never uploaded
  • The tabs permission is used only to open extension pages and to read the active tab when you ask the extension to scan a page; no scripting or webRequest permissions are used
  • Scan results are kept on the server to speed up repeat checks; see the privacy policy for details

Full privacy policy: shieldbotsecurity.online/privacy.html

Wallet & Chain Compatibility

ShieldAI hooks into the browser's window.ethereum provider at page load and is designed for:

  • Wallets that inject window.ethereum
  • Wallets announced through EIP-6963

Testing across every wallet is still in progress.

Chains supported for scans: BNB Chain, opBNB, Ethereum, Base, Arbitrum, Polygon, Optimism and Robinhood Chain. The released browser extension does not cover Robinhood Chain yet; the API and Telegram bot do.

The hook is injected into the page's MAIN world before any DApp code runs — contracts cannot detect or remove it from within a transaction.
