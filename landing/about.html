How ShieldAI Protects Your Wallet

ShieldAI checks blockchain transactions before your wallet signs them, combining contract analysis, a buy and sell simulation where the chain has one, and threat intelligence into one risk score. If a check cannot run, it says Unknown instead of Safe.

ShieldAI operates at the transaction layer, not the URL layer. In the browser's page context, before your wallet receives the request, it intercepts transactions (eth_sendTransaction, eth_signTransaction), batches (wallet_sendCalls) and signature requests (eth_signTypedData and its _v1, _v3 and _v4 forms, personal_sign and eth_sign).

What ShieldAI Does

ShieldAI is a Chrome browser extension that acts as a transaction firewall for Web3 wallets. Every time you initiate a transaction on a DApp — a swap, a token purchase, an NFT mint — ShieldAI intercepts it before your wallet receives the signature request.

The risk score combines four weighted checks: contract code (including bytecode patterns for unverified contracts), market and liquidity data, on-chain reputation, and honeypot checks (a buy and sell simulation where the chain has one), together with scam databases such as GoPlus. The result is a risk score from 0 to 100 with a plain-English explanation of what was found. For a warning, you choose whether to cancel or sign.

How Risk Is Rated

Every transaction receives a risk score before you sign it. Higher means riskier:

Risk scoreVerdictWhat you see
0 – 30SAFEThe verdict and details; you can continue
31 – 49!CAUTIONA warning; you choose to proceed or cancel
50 – 70!HIGH RISKA strong warning with threat details
71 – 100BLOCK RECOMMENDEDThe highest risk verdict; blocking is strongly recommended
—?UNKNOWN

The extension shows this as a safety score, 100 minus the risk score, so higher is safer there. These are the default bands. A score in the SAFE band is still shown as CAUTION when the risk engine rates the token medium risk or the data is incomplete, and if a check could not run the result is shown as Unknown instead of a number.

Wallet Drainer Protection

A wallet drainer is a malicious smart contract that exploits ERC-20 approval functions or EIP-712 permit signatures to transfer all tokens from a wallet in a single transaction. Standard browser phishing warnings cannot detect these because they operate at the URL layer — the attack happens at the transaction layer.

ShieldAI helps against wallet drainers by:

  • Catching the transaction or signature request before your wallet shows it
  • Analyzing EIP-712 permit and Permit2 signature requests for approval exploits
  • Flagging contracts whose deployer has a history of risky deployments
  • Showing the exact asset change before you sign, when transaction simulation is enabled

Honeypot Detection

A honeypot token allows users to buy but contains hidden code that blocks all sell transactions. The token appears to have liquidity and price action, but holders can never exit.

ShieldAI looks for honeypots in two ways. It simulates a buy and a sell of the token where the chain has a simulator: honeypot.is on Ethereum, BNB Chain and Base, and ShieldBot's own simulation on supported Arbitrum and Robinhood Chain pool routes. On Arbitrum those are pools pairing the token with WETH on Uniswap V3, Uniswap V2 or SushiSwap. On the other chains, and for an Arbitrum token with no such pool (for example one traded only on Camelot, or only against stablecoins), it uses GoPlus's honeypot and tax flags instead. It also checks the contract's bytecode for owner powers a honeypot can use, such as a blacklist or a pause switch, which works even for unverified contracts. If a simulation fails, or neither source answers, the result is Unknown rather than Safe.

Pre-Sign Transaction Simulation

When transaction simulation is enabled, ShieldAI sends the transaction to Tenderly for simulation on a copy of the chain state. Tenderly runs it in a sandbox and returns the tokens and amounts that would leave or enter your wallet.

ShieldAI displays this asset delta before the wallet signature dialog appears. For example: "You will send 2.5 BNB and receive 10,000 TOKEN." Tokens the simulation shows leaving your wallet are listed among the danger signals; they do not change the verdict itself. If the transaction reverts in the simulation, the result is incomplete and cannot be SAFE, and a revert on a contract whose own risk score, before community reports and campaign boosts, is already 30 or more is BLOCK RECOMMENDED.

ShieldAI vs. Browser Phishing Warnings

Browser built-in warnings

  • Operate at the URL / domain layer
  • Cannot inspect transaction data
  • Do not analyze smart contract code
  • Cannot simulate asset loss before signing
  • Miss all on-chain attacks on legitimate sites

ShieldAI Transaction Firewall

  • Intercepts the transaction, batch and signature methods listed above
  • Analyzes contract bytecode for honeypot/rug patterns
  • Simulates the asset change before signing, when enabled
  • Scores deployer history across past deployments
  • Flags risky Permit2 and approval signature requests

What Data ShieldAI Collects

The extension sends only what a check needs to the ShieldAI API, over HTTPS. For a transaction, or each call of a batch, that is the recipient, sender, value, calldata and chain ID, and for an EIP-7702 transaction each delegate's address, never the signed authorization. For a typed-data signature it is the signing method, any EIP-712 typed data, your address and the chain ID. For personal_sign and eth_sign it is only the signing method and the chain ID: never the message or hash you sign, and not your address. Each of these checks carries your Balanced or Strict setting. The phishing check sends only the origin (scheme, host and port) of the site you open. When you use Wallet Health, the wallet address you enter and the chain you selected are sent too.

  • Scan results are stored by contract address and chain, not with your IP address
  • Scan history (last 50 results) is stored locally in chrome.storage.local — never uploaded
  • The tabs permission is used only to open extension pages and to read the active tab when you ask the extension to scan a page; no scripting or webRequest permissions are used
  • Scan results are kept on the server to speed up repeat checks; see the privacy policy for details

Full privacy policy: shieldbotsecurity.online/privacy.html

Wallet & Chain Compatibility

ShieldAI hooks into the browser's window.ethereum provider at page load and is designed for:

  • Wallets that inject window.ethereum
  • Wallets announced through EIP-6963

Testing across every wallet is still in progress.

Chains supported for scans: Ethereum, BNB Chain, opBNB, Base, Arbitrum, Polygon, Optimism and Robinhood Chain. Version 3.1.0 of the browser extension, on the Chrome Web Store, asks the wallet which chain it is on and sends Robinhood Chain requests to the API for analysis. It has been tested with Rabby; MetaMask testing is still outstanding.

The hook is injected into the page's MAIN world before any DApp code runs — contracts cannot detect or remove it from within a transaction.
